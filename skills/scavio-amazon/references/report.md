# Report Reference

## 触发条件

用户说：报告 / 周报 / 月报 / 汇总 / summary / report / generate

## 执行流程

### Step 1 — 从 Bitable 读取历史快照

使用飞书插件「多维表格-查询记录」从 snapshots 表查询：
- filter: `记录时间 >= <7天前 或 30天前 的 ISO 8601>`
- 按「ASIN」和「记录时间」排序

同时从 products 表读取所有 active 商品的 ASIN 和商品名。

构造 stdin JSON（snapshots 顺序任意，脚本自动排序）：

```json
{
  "products": [
    {
      "asin": "B0CHWX8DFH",
      "title": "...",
      "snapshots": [
        {"sales_rank": 18, "price_value": 24.99, "fetched_at": "2026-04-18T14:20:00"}
      ]
    }
  ]
}
```

### Step 2 — 聚合报告数据

```bash
echo '<stdin json>' | python scripts/weekly_report.py --days 7   # 周报
echo '<stdin json>' | python scripts/weekly_report.py --days 30  # 月报
```

输出 JSON 包含每个商品的排名区间、价格区间、趋势判断。

### Step 3 — 写入飞书文档

使用飞书插件「更新云文档」，在文档**顶部**（监控快照区块之前）写入报告区块：

```
# 📈 {周报/月报} {起始日} ~ {结束日}

## 总览
- 监控商品：N 个
- 快照总数：M 次（每 20 分钟一次）
- 焦点商品：{title}（{asin}）· 排名变化最大

## 各商品分析

### {title}（{asin}）
排名区间：最高 #{min} · 最低 #{max} · 均值 #{avg}
价格区间：{price_min} ~ {price_max}
趋势判断：{trend_summary}

### {下一个商品...}

## 数据说明
基于 {count} 条快照记录，时间范围 {start} ~ {end}
```

### Step 4 — 发送摘要卡片

使用飞书插件「发送消息」发送报告完成通知卡片：

```
📊 {周报/月报}已生成 · {起始日}~{结束日}
─────────────────────────
监控商品：N 个  ·  快照：M 次
焦点商品：{focus_title}（排名变化 {delta}位）
─────────────────────────
[查看完整报告]  → URL 跳转到飞书文档
```

## 趋势判断标准

| 结论 | 条件 |
|------|------|
| 持续上升 | 期间排名均值优于期初，且最近 5 次均高于均值 |
| 持续下降 | 期间排名均值劣于期初，且最近 5 次均低于均值 |
| 波动 | 标准差 > 均值的 20% |
| 稳定 | 标准差 ≤ 均值的 20% |
| 数据不足 | 快照数 < 5 |

## 快照数不足时的处理

若某商品的快照数 < 5：
- 仍生成报告，但该商品趋势标注「数据不足（仅 {N} 次快照）」
- 报告总览注明「部分商品监控时间较短，趋势分析结果仅供参考」
